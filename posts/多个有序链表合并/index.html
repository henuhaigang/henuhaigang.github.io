LeetCode 多个升旭链表合并详解

6 Sep, 2026
| Edit page

合并k个有序链表的逻辑类似合并两个有序链表，难点在于，如何快速得到k个节点中的最小节点，接到结果链表上？这里我们就要用到 优先级队列（二叉堆） 这种数据结构，把链表节点放入一个最小堆，就可以每次获得k个节点中的最小节点：

ListNode mergeKLists(ListNode[] lists) {
    if (lists.length == 0) return null;
    // 虚拟头结点
    ListNode dummy = new ListNode(-1);
    ListNode p = dummy;
    // 优先级队列，最小堆
    PriorityQueue<ListNode> pq = new PriorityQueue<>(
        lists.length, (a, b)->(a.val - b.val));
    // 将 k 个链表的头结点加入最小堆
    for (ListNode head : lists) {
        if (head != null)
            pq.add(head);
    }

    while (!pq.isEmpty()) {
        // 获取最小节点，接到结果链表中
        ListNode node = pq.poll();
        p.next = node;
        if (node.next != null) {
            pq.add(node.next);
        }
        // p 指针不断前进
        p = p.next;
    }
    return dummy.next;
}

一、先不要看代码，先理解问题

假设有 3 个有序链表：

L1: 1 -> 4 -> 7
L2: 2 -> 5 -> 8
L3: 3 -> 6 -> 9

要求合并：

1 -> 2 -> 3 -> 4 -> 5 -> 6 -> 7 -> 8 -> 9

如果只有两个链表，我们刚才学过：

p1
 ↓
1 -> 4 -> 7

p2
 ↓
2 -> 5 -> 8

每次比较：

p1.val
p2.val

谁小就拿谁。

因为只有两个候选，所以非常简单。

二、但是现在是 K 个链表

假设：

L1: 1 -> 4 -> 7
L2: 2 -> 5 -> 8
L3: 3 -> 6 -> 9

第一次有三个候选：

1
2
3

我们找：

min(1, 2, 3) = 1

拿走 1。

那么 L1 的下一个节点：

4

进入候选。

现在候选变成：

4
2
3

找最小：

min(4, 2, 3) = 2

拿走 2。

L2 下一个：

5

进入候选：

4
5
3

再找：

min(4, 5, 3) = 3

……

你应该已经看出来了：

每次都要从 K 个节点里面找最小值。

三、最笨的方法是什么？

每次遍历 K 个链表：

int min = Integer.MAX_VALUE;

for (每个链表) {
    找当前节点；
}

例如 K = 1000：

第 1 次：比较 1000 个
第 2 次：比较 1000 个
第 3 次：比较 1000 个
...

如果总共有 N 个节点：

时间复杂度 ≈ O(NK)

K 很大的时候就比较慢。

四、PriorityQueue 是干什么的？

它解决的问题非常简单：

我有一堆东西，我希望随时快速拿出“优先级最高”的那个。

在我们的题目里：

优先级最高 = val 最小。

所以我们使用：

最小堆（Min Heap）

五、先把“优先队列”理解成一个特殊的容器

假设：

PriorityQueue<Integer>

里面放：

5
2
8
1
3

普通 List：

[5, 2, 8, 1, 3]

你想找最小值：

1

得遍历：

5
2
8
1
3

复杂度：

O(K)

但是 PriorityQueue 会帮你维护一种特殊结构：

        1
       / \
      2   3
     / \
    5   8

这叫：

最小堆（Min Heap）

它保证：

父节点 <= 子节点

所以：

最小值永远在顶部。

因此：

pq.poll()

可以快速拿到最小值。

六、这里你一定要区分三个操作

PriorityQueue 最重要的就是：

add()
peek()
poll()

1. add()

pq.add(x);

意思：

把 x 放进优先队列。

例如：

pq:
5
2
8

执行：

pq.add(1);

PriorityQueue 会自动调整内部堆结构。

你不需要自己排序。

七、peek()

pq.peek()

意思：

看看当前优先级最高的元素是谁，但不要删除。

例如：

pq = [1, 2, 3, 5, 8]

：

pq.peek()

得到：

1

但是 1 还在。

八、poll()

pq.poll()

意思：

拿走并删除当前优先级最高的元素。

例如：

pq:
1
2
3
5
8

执行：

ListNode node = pq.poll();

得到：

node = 1

同时 PriorityQueue 里面：

2
3
5
8

1 被移除了。

九、所以这个算法真正依赖的是

pq.poll()

每次：

从当前所有候选节点中拿出最小的那个。

这就是整个算法最核心的地方。

十、现在来看你的代码

第一行

if (lists.length == 0) return null;

如果：

lists = []

没有任何链表。

那结果自然：

null

十一、创建 dummy

ListNode dummy = new ListNode(-1);

跟我们刚才学的一模一样：

dummy
 ↓
-1

它是结果链表的固定锚点。

十二、创建 p

ListNode p = dummy;

所以：

dummy
  ↓
 -1
  ↑
  p

以后：

p.next = node;

就是不断往结果链表尾部添加节点。

十三、重点来了：创建 PriorityQueue

PriorityQueue<ListNode> pq = new PriorityQueue<>(
    lists.length,
    (a, b) -> (a.val - b.val)
);

这行一定要拆开。

十四、PriorityQueue<ListNode>

意思：

这个优先队列里面存放的东西是 ListNode。

所以：

pq
 ↓
ListNode
ListNode
ListNode
...

而不是：

pq
 ↓
int

十五、lists.length

这是：

PriorityQueue` 的初始容量。

比如：

lists.length = 3

就是：

new PriorityQueue<>(3, ...)

意思是：

一开始准备一个容量大约为 3 的优先队列。

注意：这不是队列最大只能放 3 个元素。

这是很多人第一次看到这里容易误解的地方。

PriorityQueue 会自动扩容。

十六、最关键的是 comparator

(a, b) -> (a.val - b.val)

这是告诉 PriorityQueue：

ListNode 怎么比较大小？

因为 Java 默认不知道：

ListNode A
ListNode B

谁更小。

但是你告诉它：

(a, b) -> a.val - b.val

那么：

a.val < b.val

就认为：

a < b

所以：

val 越小
 ↓
优先级越高
 ↓
越靠近堆顶

因此这是：

最小堆。

十七、举个具体例子

现在：

L1: 1 -> 4 -> 7
L2: 2 -> 5 -> 8
L3: 3 -> 6 -> 9

执行：

for (ListNode head : lists) {
    if (head != null)
        pq.add(head);
}

第一次 add

pq.add(L1.head);

加入：

1

现在：

pq
 ↓
1

第二次 add

pq.add(L2.head);

加入：

2

内部堆：

   1
   |
   2

第三次 add

pq.add(L3.head);

加入：

3

概念上：

    1
   / \
  2   3

所以：

pq 顶部 = 1

十八、注意一个非常重要的事情

PriorityQueue 不是普通队列。

普通 Queue：

先进先出

1 -> 2 -> 3

poll()
 ↓
1

PriorityQueue：

按照优先级取出

5
2
8
1
3

poll()
 ↓
1

再：

poll()
 ↓
2

再：

poll()
 ↓
3

所以它叫：

优先队列

而不是普通队列。

十九、现在进入 while

while (!pq.isEmpty())

意思：

只要还有候选节点，就继续。

二十、这一行是整个算法的灵魂

ListNode node = pq.poll();

现在 PriorityQueue：

    1
   / \
  2   3

执行：

node = pq.poll();

得到：

node = 1

并且：

pq:
2
3

所以：

node
 ↓
1 -> 4 -> 7

注意！

这里只是把“节点 1”从 PriorityQueue 中拿出来。

并没有把：

1 -> 4 -> 7

整个链表都拿出来。

二十一、然后：

p.next = node;

现在：

p
↓
dummy -> -1

所以：

dummy -> -1 -> 1

二十二、接下来是整个算法最漂亮的地方

if (node.next != null) {
    pq.add(node.next);
}

我们刚刚从 L1 里面拿走了：

1

那么 L1 当前最重要的下一个候选是谁？

4

所以：

pq.add(node.next);

把：

4

放进 PriorityQueue。

现在：

pq:
2
3
4

于是：

下一次 poll()

自然得到：

2

二十三、这就是整个算法最关键的思想

你一定要理解：

PriorityQueue 里永远只放每个链表“当前最小的那个节点”。

例如：

L1: 1 -> 4 -> 7
L2: 2 -> 5 -> 8
L3: 3 -> 6 -> 9

开始：

pq:

1  ← L1 当前最小
2  ← L2 当前最小
3  ← L3 当前最小

拿走：

1

那么 L1 的新候选：

4

所以：

pq:

2
3
4

拿走：

2

L2 新候选：

5

所以：

pq:

3
4
5

拿走：

3

L3 新候选：

6

所以：

pq:

4
5
6

……

这就是：

每次淘汰一个最小节点，然后从这个节点所属的链表补进下一个候选。

二十四、整个过程画出来

L1: 1 -> 4 -> 7
     ↑

L2: 2 -> 5 -> 8
     ↑

L3: 3 -> 6 -> 9
     ↑

     ↓
   PriorityQueue
     ↓

   [1, 2, 3]
       ↓
     poll
       ↓
       1
       ↓
   [2, 3, 4]
       ↓
     poll
       ↓
       2
       ↓
   [3, 4, 5]
       ↓
     poll
       ↓
       3
       ↓
   [4, 5, 6]
       ↓
     poll
       ↓
       4

二十五、然后这行

p = p.next;

和我们上一题完全一样。

之前：

dummy -> 1 -> 2 -> 3
                   ↑
                   p

p 永远指向：

当前结果链表的最后一个节点。

所以：

p.next = node;
p = p.next;

其实就是：

把新节点接到结果尾部，然后让 p 移动到新尾部。

二十六、最后

return dummy.next;

还是刚才的套路：

dummy
 ↓
-1 -> 1 -> 2 -> 3 -> 4 -> 5 -> 6
      ↑
      dummy.next

返回：

1 -> 2 -> 3 -> 4 -> 5 -> 6

二十七、现在说说为什么它比暴力方法快

假设：

K = 链表数量
N = 所有节点总数

每一次：

pq.poll()

PriorityQueue 需要调整堆。

复杂度：

O(log K)

每个节点只会：

add 一次
poll 一次

所以总复杂度：

O(N log K)

空间：

O(K)

因为 PriorityQueue 中最多保存 K 个候选节点。

二十八、为什么 PriorityQueue 里最多只有 K 个节点？

这是这道题非常重要的理解。

假设：

K = 3

我们有：

L1
L2
L3

每个链表只放：

当前正在考虑的一个节点。

所以：

pq
 ↓
L1 当前节点
L2 当前节点
L3 当前节点

最多：

3 个

即：

K 个

当你：

pq.poll()

拿走一个：

K - 1

然后：

pq.add(node.next)

又补回来：

K

所以 PriorityQueue 一直维持一个非常漂亮的状态：

K 个链表，每个链表最多贡献一个候选节点。

二十九、你可以把 PriorityQueue 想象成“擂台”

这个比喻非常好理解。

三个链表：

L1: 1 -> 4 -> 7
L2: 2 -> 5 -> 8
L3: 3 -> 6 -> 9

现在擂台上：

      PriorityQueue

      1   2   3
      ↓   ↓   ↓
     L1  L2  L3

裁判：

“谁最小？”

1。

于是：

1 出局

L1：

1 -> 4 -> 7
     ↑

马上派：

4

上擂台：

      PriorityQueue

      2   3   4
      ↓   ↓   ↓
     L2  L3  L1

裁判：

“谁最小？”

2。

然后 L2 派：

5

继续。

三十、所以这个算法其实由两个套路组成

你现在应该把它拆成：

套路一：dummy + p

负责：

构造结果链表

也就是：

ListNode dummy = new ListNode(-1);
ListNode p = dummy;

以及：

p.next = node;
p = p.next;

套路二：PriorityQueue

负责：

从 K 个候选节点中快速找最小值

也就是：

PriorityQueue<ListNode> pq =
    new PriorityQueue<>(
        lists.length,
        (a, b) -> a.val - b.val
    );

以及：

ListNode node = pq.poll();

三十一、你现在真正应该掌握的是这个抽象

以后看到：

“K 个有序序列，需要合并/找最小值/找最大值”

马上想到：

K 个有序链表
      ↓
每个链表只拿一个当前候选
      ↓
PriorityQueue
      ↓
每次取最小
      ↓
从对应序列补下一个

这其实不仅仅是链表。

三十二、这个思想还能解决很多问题

例如：

合并 K 个有序数组

A: 1 4 7
B: 2 5 8
C: 3 6 9

完全一样：

PriorityQueue

找 K 个有序文件中的最小值

例如日志：

file1: 01:00 01:05 01:10
file2: 01:02 01:04 01:11
file3: 01:03 01:06 01:08

要做归并：

PriorityQueue

这实际上就是很多数据库、日志系统、MapReduce/Spark 类系统里非常经典的：

K-way merge（K 路归并）

三十三、还有一个 Java 细节，我建议你现在就改掉

你代码里面：

(a, b) -> (a.val - b.val)

虽然这道题通常没问题，但更规范的写法是：

(a, b) -> Integer.compare(a.val, b.val)

因为：

a.val - b.val

理论上可能整数溢出。

所以建议：

PriorityQueue<ListNode> pq =
    new PriorityQueue<>(
        lists.length,
        (a, b) -> Integer.compare(a.val, b.val)
    );

三十四、最后给你一个“算法思维升级”

刚才的两个题：

两个链表

p1 + p2

你做的是：

比较两个候选
    ↓
取小的
    ↓
移动对应指针

K 个链表

变成：

p1 + p2 + p3 + ... + pk

如果继续写：

if p1 < p2
if p1 < p3
if p1 < p4
...

代码会越来越丑。

于是我们抽象出：

“我要维护 K 个候选值，并快速找到最小值。”

于是：

K 个指针
   ↓
K 个候选节点
   ↓
PriorityQueue
   ↓
每次 O(log K) 找最小

这就是算法真正的进阶方式：

不是记住“合并 K 个链表使用 PriorityQueue”，而是从“每次需要在 K 个候选者中快速找最小值”这个问题，推导出 PriorityQueue。

你现在可以把这道题记成一张脑图

                    合并 K 个有序链表
                           │
             ┌─────────────┴─────────────┐
             ↓                           ↓
        如何构造结果？              如何找最小？
             ↓                           ↓
        dummy + p                  PriorityQueue
             │                           │
       dummy 固定不动              K 个候选节点
       p 指向结果尾部              每个链表一个
             │                           │
             └──────────┬────────────────┘
                        ↓
                  poll 最小节点
                        ↓
                  接到 p 后面
                        ↓
              把 node.next 放回 PQ
                        ↓
                       循环

这就是这道题最核心的全部逻辑。

下一步非常适合继续学一个和它高度相关、但思维又进一步的套路：为什么 PriorityQueue 底层是“堆”，堆到底是怎么做到 add O(logK)、poll O(logK) 的，以及 Java 的 PriorityQueue 内部数组到底长什么样。 这一步吃透以后，你以后遇到“Top K、前 K 小/大、合并 K 路、实时最值”这类题，就会真正知道为什么该用堆，而不是只知道“答案说用 PriorityQueue”。
