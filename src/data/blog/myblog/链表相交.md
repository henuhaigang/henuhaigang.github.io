**力扣 160「相交链表」真正值得掌握的不是代码，而是“双指针为什么能让两个指针在同一个位置相遇”。**

这道题是链表题里非常经典的一道，我建议你把它理解成一个**“消除两条链表长度差”**的问题。

---

# 一、先把题目搞清楚：什么叫“相交”？

假设：

```text
链表 A：

a1 → a2 → a3
             ↘
               c1 → c2 → c3
             ↗
b1 → b2 → b3

链表 B：
```

实际上两个链表的结构是：

```text
A: a1 → a2 → a3 ─┐
                 ↓
                 c1 → c2 → c3 → null
                 ↑
B: b1 → b2 → b3 ─┘
```

那么：

```text
headA = a1
headB = b1
```

相交节点：

```text
c1
```

注意一个非常重要的点：

> **相交指的是两个链表引用的是同一个 Node 对象，而不是两个节点的值相同。**

比如：

```java
A:
a1 → 7 → 8

B:
b1 → 7 → 8
```

即使两个 `7` 的值相同，也不算相交。

必须是：

```java
A: a1 → a2 ─┐
            ↓
            c1 → c2
            ↑
B: b1 → b2 ─┘
```

也就是：

```java
a2.next == b2.next
```

引用指向同一个节点。

---

# 二、最容易想到的方法：暴力

我们可以：

```text
遍历 A
    对每一个 A 节点
        遍历 B
            判断两个节点是不是同一个节点
```

伪代码：

```java
for (Node p = headA; p != null; p = p.next) {
    for (Node q = headB; q != null; q = q.next) {
        if (p == q) {
            return p;
        }
    }
}

return null;
```

这里一定是：

```java
p == q
```

而不是：

```java
p.val == q.val
```

时间复杂度：

```text
O(N × M)
```

显然不是最优。

---

# 三、进一步思考：相交链表有什么特殊结构？

这是这道题最关键的地方。

如果两个链表相交，那么它们**从相交点开始，后面的部分一定完全一样**。

例如：

```text
A:

a1 → a2 → a3
             \
              c1 → c2 → c3 → null
             /
B:

b1 → b2 → b3
```

可以把它看成：

```text
A 独有部分：a1 → a2 → a3
B 独有部分：b1 → b2 → b3
公共部分：  c1 → c2 → c3
```

也就是说：

```text
A = A独有 + 公共部分

B = B独有 + 公共部分
```

假设：

```text
A 独有长度 = 3
B 独有长度 = 5
公共部分长度 = 4
```

那么：

```text
A长度 = 3 + 4 = 7
B长度 = 5 + 4 = 9
```

两条链表长度不一样。

# 四、为什么普通双指针会失败？

最直接的双指针：

```java
p = headA;
q = headB;

while (p != q) {
    p = p.next;
    q = q.next;
}
```

看起来很漂亮。

但是问题是：

```text
A: a1 → a2 → a3 → c1 → c2 → c3
B: b1 → b2 → b3 → b4 → b5 → c1 → c2 → c3
```

A 长度：

```text
6
```

B 长度：

```text
8
```

两个指针同时走：

```text
第1步：

p = a2
q = b2

第2步：

p = a3
q = b3

第3步：

p = c1
q = b4

第4步：

p = c2
q = b5

第5步：

p = c3
q = c1
```

已经错开了。

---

# 五、真正的核心：让两个指针“走过相同的路程”

这就是这道题最漂亮的地方。

我们让：

```text
p：走 A → B

q：走 B → A
```

也就是：

```java
p = headA;
q = headB;

while (p != q) {
    p = p == null ? headB : p.next;
    q = q == null ? headA : q.next;
}
```

你先别急着背代码。

我们从数学上理解为什么。

---

# 六、假设两条链表相交

假设：

```text
A 独有部分长度 = a
B 独有部分长度 = b
公共部分长度 = c
```

那么：

```text
A = a + c
B = b + c
```

两个指针的运动路线：

### p：

先走 A：

```text
a + c
```

然后走 B：

```text
b + c
```

总路程：

```text
a + c + b + c
```

### q：

先走 B：

```text
b + c
```

然后走 A：

```text
a + c
```

总路程：

```text
b + c + a + c
```

两者完全相同：

```text
a + b + 2c
```

这就是整个算法的核心。

---

# 七、为什么交换链表就能消除长度差？

我们具体看。

假设：

```text
A：

a1 → a2 → a3 → c1 → c2 → c3
```

```text
B：

b1 → b2 → b3 → b4 → b5 → c1 → c2 → c3
```

那么：

```text
A 独有 = 3
B 独有 = 5
公共 = 3
```

所以：

```text
A = 3 + 3 = 6
B = 5 + 3 = 8
```

现在：

```text
p 从 A 开始
q 从 B 开始
```

第一轮：

```text
p 走 A
q 走 B
```

当：

```text
p 走完 A
```

它开始：

```text
p → B
```

而：

```text
q 走完 B
```

开始：

```text
q → A
```

于是：

```text
p 的路线：

A独有 → 公共 → B独有 → 公共
```

```text
q 的路线：

B独有 → 公共 → A独有 → 公共
```

把它展开：

```text
p：

a1 → a2 → a3 → c1 → c2 → c3 → b1 → b2 → b3 → b4 → b5 → c1
                                                                    ↑
                                                                    |
                                                                    p


q：

b1 → b2 → b3 → b4 → b5 → c1 → c2 → c3 → a1 → a2 → a3 → c1
                                                                    ↑
                                                                    |
                                                                    q
```

最后它们会同时到达：

```text
c1
```

---

# 八、一个非常重要的理解：不是“走到 null 就结束”

代码：

```java
p = p == null ? headB : p.next;
```

很多初学者看到这里会疑惑：

> p 都已经 null 了，为什么不直接结束？

因为：

```text
null
```

在这里其实承担了一个非常重要的作用。

它相当于：

> **告诉我们：我已经把第一条链表走完了，现在开始走第二条链表。**

所以：

```text
p：

headA
  ↓
A → A → A → null
              ↓
            headB
              ↓
B → B → B → null
```

也就是说：

```text
null → headB
```

逻辑上可以理解成：

```text
A + B
```

---

# 九、代码到底应该怎么写？

标准写法：

```java
public ListNode getIntersectionNode(ListNode headA, ListNode headB) {

    ListNode p = headA;
    ListNode q = headB;

    while (p != q) {

        if (p == null) {
            p = headB;
        } else {
            p = p.next;
        }

        if (q == null) {
            q = headA;
        } else {
            q = q.next;
        }
    }

    return p;
}
```

也可以写得更加简洁：

```java
public ListNode getIntersectionNode(ListNode headA, ListNode headB) {

    ListNode p = headA;
    ListNode q = headB;

    while (p != q) {
        p = (p == null) ? headB : p.next;
        q = (q == null) ? headA : q.next;
    }

    return p;
}
```

我更推荐你记第二种。

---

# 十、这里最容易犯的错误：`p.val == q.val`

千万不要写：

```java
while (p.val != q.val)
```

因为题目判断的是：

```text
是不是同一个节点
```

而不是：

```text
值是不是一样
```

所以：

```java
p == q
```

才是正确的。

例如：

```text
A：

1 → 2 → 8 → 4 → 5


B：

3 → 9 → 8 → 4 → 5
```

如果两个 `8` 是不同对象：

```java
p.val == q.val
```

虽然：

```text
8 == 8
```

但是：

```java
p != q
```

所以没有相交。

---

# 十一、如果两个链表完全不相交呢？

这个情况也非常漂亮。

例如：

```text
A：

a1 → a2 → a3 → null


B：

b1 → b2 → b3 → b4 → null
```

p：

```text
A → null → B → null
```

q：

```text
B → null → A → null
```

它们最终都会变成：

```text
null
```

所以：

```java
p == q
```

成立。

然后：

```java
return p;
```

返回：

```text
null
```

所以你甚至不需要额外写：

```java
if (没有相交) {
    return null;
}
```

算法自然就处理了。

---

# 十二、为什么一定能够相遇？

这是面试中非常值得你说出来的一句话。

假设：

```text
A长度 = m
B长度 = n
```

p 的路线：

```text
A + B
```

所以总长度：

```text
m + n
```

q 的路线：

```text
B + A
```

总长度：

```text
n + m
```

因此：

```text
m + n = n + m
```

两个指针最终走过的路程完全一样。

如果存在相交节点，那么它们在经过长度差的抵消后，会在第一个公共节点相遇。

如果不存在相交节点，那么它们会同时到达：

```text
null
```

所以：

```text
有交点 → 在交点相遇

无交点 → 在 null 相遇
```

---

# 十三、你可以把它理解成“路线互换”

这是我认为最好记忆的一种方式。

不要死记：

```java
p = p == null ? headB : p.next;
q = q == null ? headA : q.next;
```

而是记：

> **两个指针分别走完自己的链表之后，去走对方的链表。**

也就是：

```text
p：

A → B


q：

B → A
```

于是：

```text
p 总路程 = A + B
q 总路程 = B + A
```

因此它们一定走一样远。

---

# 十四、画图理解一下就非常直观了

假设：

```text
A：

      a1 → a2 → a3
                    \
                     c1 → c2 → c3 → null
                    /
      b1 → b2 → b3


B：
```

p：

```text
a1 → a2 → a3 → c1 → c2 → c3 → null
                                      ↓
                                     b1 → b2 → b3 → c1
                                                      ↑
                                                      |
```

q：

```text
b1 → b2 → b3 → c1 → c2 → c3 → null
                                      ↓
                                     a1 → a2 → a3 → c1
                                                      ↑
                                                      |
```

最后：

```text
p = c1
q = c1
```

于是：

```java
p == q
```

退出循环。

# 十五、为什么时间复杂度是 O(N + M)？

假设：

```text
A长度 = N
B长度 = M
```

p 最多走：

```text
N + M
```

q 最多走：

```text
M + N
```

所以：

```text
时间复杂度 = O(N + M)
```

空间方面只使用：

```text
p
q
```

两个变量：

```text
空间复杂度 = O(1)
```

这是这道题最优的解法。

---

# 十六、还有一种解法：先计算长度

这也是非常经典的解法。

先计算：

```text
lenA
lenB
```

例如：

```text
A = 7
B = 10
```

那么：

```text
B 比 A 长 3
```

所以让 B 的指针先走：

```text
3步
```

变成：

```text
A：

a1 → a2 → a3 → a4 → c1 → c2 → c3


B：

b1 → b2 → b3 → b4 → b5 → b6 → c1 → c2 → c3
                              ↑
                              |
                         B指针先走3步
```

此时两个指针距离相交点相同：

```text
p = a1
q = b4
```

然后：

```java
while (p != q) {
    p = p.next;
    q = q.next;
}
```

最终：

```text
p = c1
q = c1
```

# 十七、两种方法怎么选？

### 方法一：求长度 + 对齐

逻辑：

```text
1. 求 A 长度
2. 求 B 长度
3. 让长链表指针先走差值
4. 两个指针一起走
5. 找到相同节点
```

优点：

> 非常容易理解。

缺点：

> 代码稍微多一些。

---

### 方法二：双指针交换链表

```text
p：A → B

q：B → A
```

优点：

> 代码非常短，而且是 O(1) 空间。

缺点：

> 第一次接触时不太容易理解为什么成立。

面试的时候我建议你使用：

**双指针交换链表。**

但是如果面试官问：

> “你是怎么想到的？”

你就可以从：

```text
两条链表长度可能不同
        ↓
先想办法消除长度差
        ↓
长链表多出来的部分就是问题
        ↓
让 p 走 A+B
让 q 走 B+A
        ↓
两个人走过的总路程相同
        ↓
最终在交点相遇
```

这样讲，思路会非常完整。

# 十八、这道题真正考察的是什么？

表面上：

> 找两个链表的相交节点。

实际上考的是三个东西。

### ① 链表节点的“引用相等”

```java
p == q
```

不是：

```java
p.val == q.val
```

---

### ② 能不能发现“长度差”这个问题

两个链表：

```text
A = a + c
B = b + c
```

真正的问题就是：

```text
a != b
```

---

### ③ 能不能通过重新规划路线消除长度差

这是最核心的思想：

```text
p：A → B
q：B → A
```

把：

```text
A + B
```

和：

```text
B + A
```

变成完全相同的长度。

---

# 十九、你可以把这道题记成一句话

如果以后面试或者刷题时忘记代码，只要想起来：

> **“两个指针，分别走自己的链表，再走对方的链表。”**

就基本能把代码推出来：

```java
ListNode p = headA;
ListNode q = headB;

while (p != q) {
    p = p == null ? headB : p.next;
    q = q == null ? headA : q.next;
}

return p;
```

最后再给你一个非常重要的抽象：

```text
p = A + B
q = B + A
```

所以：

```text
p 的总路程 = q 的总路程
```

**有交点：**

```text
          ↓
p ─────── c1
q ─────── c1
```

**没交点：**

```text
p ─────── null
q ─────── null
```

这就是 LeetCode 160 的核心。
